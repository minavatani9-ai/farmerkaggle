## 2. AGENT ARCHITECTURE (from the champion "Friday 2148")

The agent has a **layered architecture** — understand each layer before changing anything:

### Layer 1: `_PLAN` (frozen 719-tick action script)
- A `zlib`-compressed JSON blob containing one exact action per tick
- Contains farmer movement, hand assignments, and market orders for every tick
- This IS the strategy — it was generated by some prior optimization process
- It is NOT tunable by editing parameters; it's a literal recorded action sequence
- Used via `_scheduled(observation, tick)` which simply looks up `_PLAN[tick]`

### Layer 2: `_production_agent` / `_baseline_agent`
- `_baseline_agent`: runs `_scheduled()` for ticks 0-705; for ticks 706-718
  does a shed-liquidation sell
- `_production_agent`: wraps `_baseline_agent`, adds `_adjust_herd()` (animal
  population management) and re-projects shed stock for SELL orders during
  ticks 168-706

### Layer 3: `_exp119_agent`
- For ticks 696-718: switches from `_production_agent` to `plan()` (a live
  adaptive vehicle-routing algorithm)
- For all other ticks: delegates to `_production_agent`
- `plan()` is a genuine live planner that reads real tile states, but it
  disagrees with `_PLAN` on 715/719 ticks — it's essentially a different,
  much simpler agent. DO NOT extend its window without the real simulator.

### Layer 4: `_repair_purchase`
- Runs AFTER `_exp119_agent`
- Fixes cash-shortfall on early livestock purchases by selling uncommitted stock
- Proven safe; does not change farm actions

### Layer 5 (my addition, NOT proven to help): `_throttle_sales`
- Trims SELL orders when marginal price < 25% of base price
- Verified to improve revenue in self-play simulation (+5-20k on 250k base)
- But ALL three throttle submissions scored below the non-throttle base range
- **Recommendation: REMOVE the throttle for the next submission and test
  whether the base code returns to the 2200-2500 range. If it does, the

## 5. WHAT HAS BEEN TRIED AND FAILED

### Sell-throttle (withhold goods when price is below 25% of base)
- **Mechanism is real**: in self-play replay simulation, saves +5-20k revenue
  by avoiding floor-price sales of MILK, WOOL, FERTILIZER
- **But hurts in competitive play**: all 3 throttle submissions scored 1700-1850,
  below the 2189-2540 non-throttle range
- **Why it probably hurts**: withholding goods keeps market inventory lower,
  which raises prices for the OPPONENT who sells normally. You sacrifice
  liquidity timing for a price improvement that benefits both players equally.
- **Verdict**: Remove it. The base code without throttle is stronger.

### Extending plan()'s live window (from ticks 696-718 to earlier)
- **Tested**: plan() runs cleanly at all ticks but disagrees with _PLAN on
  715/719 ticks — it's essentially a DIFFERENT, much simpler agent
- **At tick 0** (empty board, fully deterministic): plan() issues 10 HIRE orders
  while _PLAN issues a calibrated BUY_PRODUCT/SELL opening. Clearly worse.
- **Cannot be validated without the real game simulator** (kaggle-environments)
  because changing farm actions changes board state, making replay-based
  comparison invalid past tick 0
- **Verdict**: Do not attempt without the real simulator.

### _prioritize_sales (from the "sunday535am" submission)
- Reordered SELL commands using a hand-guessed price-impact model
- Crashed when obs['market']['inventory'] had unexpected keys (though we later
  confirmed the key DOES exist — the crash was in my synthetic test, not live)
